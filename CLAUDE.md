# Project: naive_bayes_101

> Naive Bayes from scratch, on CPU. 6 notebooks → 1 Streamlit app → `src/` library.
> The "wrong" model that refuses to lose.

## Thesis (read this first — it drives every design choice)

Naive Bayes rests on an assumption — every feature is independent of every other
given the class — that is **provably false on essentially all real data**. Yet it
classifies spam and text about as well as far heavier methods, trains in a **single
counting pass** with no optimization loop, and **beats logistic regression when data
is scarce** because it cannot overfit where a flexible model does. The catch: its
predicted probabilities are **absurdly overconfident** (pinned near 0 and 1), because
multiplying many correlated "independent" probabilities compounds the error.

The permanent lesson this repo exists to teach:
**getting the class right and getting the probability right are two different things.**
Naive Bayes gets the decision right for the wrong reasons — the cleanest example of a
right-decision / wrong-probability model in all of ML. **Trust its decisions, never
its probabilities.**

The build-up, notebook by notebook:
`Bayes → classifier` → `Naive Bayes is counting` → `the spam filter` →
`right decision, wrong probability` → `when it wins and loses` → `practical guide`.

## Models — non-negotiable rules

- **Build the three NB variants from scratch** (numpy/scipy only in the model code —
  no `sklearn.naive_bayes` inside `src/models/`). sklearn is for the *comparison
  baselines* (logistic regression) and for *parity tests*, not for the model itself.
- **From-scratch must match sklearn to `1e-9`** on the same data — this is tested
  (`test_gaussian_nb.py`, `test_multinomial_nb.py`). If a change breaks parity, the
  change is wrong, not the test.
- Work in **log space** (sum of log-likelihoods, not product of probabilities) to avoid
  underflow — this is also what makes the overconfidence visible and honest.
- **Smoothing is a requirement, not a refinement.** An unseen feature gives probability
  0 and annihilates the whole prediction. Laplace (additive) smoothing adds a small
  count so no probability is ever exactly 0. `test_smoothing.py` asserts no probability
  collapses to zero.
- Match the **model form to the feature type**: Gaussian ↔ continuous, Multinomial ↔
  counts, Bernoulli ↔ binary. Don't mix them.

## Key domain concepts (keep these straight)

- Naive Bayes picks the class maximizing `P(class) · ∏ P(feature | class)`. The `∏`
  (treating features as independent) is where the false assumption lives.
- **Training is counting.** Single pass, no gradient descent, no tuning loop — just
  tallies (word counts, or per-class means/variances). This is why it's fast,
  data-efficient, and streaming-updatable. Don't add optimization where none belongs.
- **Right decision, wrong probability.** Errors from false independence often affect all
  classes similarly and cancel in the `argmax`, so the ranking stays correct — but they
  wreck the numbers, pushing probabilities toward 0/1. More feature correlation →
  more overconfidence. The **duplicated-feature worst case** (perfect correlation) makes
  this exact and is **asserted in `test_overconfidence.py`**: accuracy barely moves while
  overconfidence climbs.
- **When it wins:** text / bag-of-words, high-dimensional sparse data, tiny training
  sets, and as the strong baseline a heavier model must beat. **When it loses:** strongly
  correlated features and problems where feature interactions matter.
- If you need calibrated probabilities from NB, **recalibrate** (isotonic / Platt) —
  don't trust the raw numbers.

## Datasets & reproducibility

- **Seed everything.** Data generation and train/test splits are seeded from
  `config/settings.yaml`. Claims (data-efficiency crossover, overconfidence-vs-correlation)

## Streamlit app (`app/streamlit_app.py`) — 4 demos

1. **Spam classifier** — type a message, see the NB score, with spam-pushing words highlighted.
2. **Counting viewer** — pick a class, see the per-feature counts that *are* the trained model.
3. **Overconfidence demo** — add a duplicated feature, watch probability march to 0.9999 while accuracy stays flat.
4. **Data-efficiency race** — shrink the training set, watch NB overtake logistic regression.

- `ruff` config lives in `pyproject.toml`: line length **99**, target `py311`, rule set

- Type-check `src/` with **`ty`** (`make typecheck`). Add type hints to public functions.
- Config is loaded via **pydantic-settings** from `config/settings.yaml` — read values
  from there, don't hard-code smoothing α, seeds, or sample sizes in modules/notebooks.
- Use `pathlib` for paths (ruff `PTH` enforces it).
- **Ruff carve-out:** `N803`/`N806` are ignored so `X` (feature matrix) is allowed — the

- **Build & interpreter:** installable package via hatchling (`packages = ["src"]`), so

  and notebooks work from any directory. Python is pinned to **3.12** in `.python-version`
  (the "3.11+" floor, chosen for reliable wheels); pytest adds the repo root via
  `pythonpath = ["."]`.

## Definition of done (success criteria)

A change is done when, as applicable:
- From-scratch Gaussian/Multinomial NB match sklearn to `1e-9`.
- Multinomial NB spam accuracy is competitive with logistic regression and trains faster.
- NB beats logistic regression as the training set shrinks (demonstrated, with the crossover shown honestly).
- Unsmoothed + unseen feature → prediction annihilated; smoothing fixes it (asserted).
- Reported probabilities on correct predictions are pinned near 0/1 with log loss quantified.
- Duplicated feature increases overconfidence while accuracy barely moves (asserted).
- Top spam-indicating words are surfaced from the counts.
- **`make lint` and `make test` pass with zero errors**, and touched notebooks run < 4 min.
